Climbing Stairs: Why ways(n) = ways(n - 1) + ways(n - 2) Actually Works

One of the most common Dynamic Programming problems is the Climbing Stairs problem.

It looks simple:

You are climbing a staircase with n steps. At each move, you can climb either 1 step or 2 steps. How many distinct ways can you reach the top?

The solution is often written as:

ways(n) = ways(n - 1) + ways(n - 2)

The formula is easy to memorize. But memorizing it is not the goal. The important question is:

Why exactly does this formula work?

And there is a very natural doubt here:

If I reach n - 1 and then take 1 step, or reach n - 2 and then take 2 steps, shouldn't I also explicitly count those final 1-step and 2-step moves?

Yes, we are counting them. In fact, understanding where those final moves are counted is the key to understanding the recurrence.

1. First, Restate the Problem

Suppose we have a staircase with n steps.

We start at the ground, which we can think of as step 0. From any position, we can:

  • move up by 1 step, or
  • move up by 2 steps.

We need to count how many different sequences of 1-step and 2-step moves will take us exactly to step n.

For example, if n = 3, the possible ways are: 

1 + 1 + 1
1 + 2
2 + 1

Therefore: 

ways(3) = 3

2. What Category of Problem Is This?

This is a classic Dynamic Programming problem.

More specifically, it demonstrates an important DP idea:

  • Define a state.
  • Find how the current state depends on smaller states.
  • Reuse answers to smaller states instead of recalculating them.

The problem also has a strong connection to the Fibonacci sequence, because its recurrence has the same form.

3. Before DP: What Would Brute Force Do?

Let's first ignore Dynamic Programming.

At every step, we have two choices: 

Take 1 step
OR
Take 2 steps

So we could recursively try both possibilities.

For example: 

                    Start
                   /     \
                 +1       +2
                /           \
              +1             +1
             /  \             \
           +1    +2            ...

This creates a decision tree.

As n becomes larger, the number of branches grows exponentially.

So a straightforward recursive solution repeatedly solves the same smaller problems.

For example, ways(5) needs ways(4) and ways(3).

But ways(4) itself needs ways(3) and ways(2).

So ways(3) gets calculated multiple times.

The big DP idea is: if we have already solved a smaller problem, don't solve it again.

4. The Most Important Question: What Does ways(n) Mean?

This definition is extremely important.

When we write: 

ways(n)

we mean:

The total number of different ways to reach exactly step n.

It does not mean:

  • the number of steps needed to reach n, or
  • the number of ways to make the next move, or
  • the number of ways to arrange only the final 1 or 2 steps.

It represents the entire history of moves that gets us from the start to step n.

5. The Key Insight: Look at the Last Move

Instead of asking:

"How can I construct every possible way to reach step n?"

ask a much simpler question:

What could my final move have been?

There are only two possibilities.

Possibility 1: The last move was 1 step

If my final move was a 1-step move, then immediately before that move I must have been at: 

n - 1

Then I take one final step: 

n - 1  →  n
         +1

How many ways are there to get to n - 1? 

ways(n - 1)

Therefore, there are exactly ways(n - 1) complete paths to n whose final move is 1 step.

Possibility 2: The last move was 2 steps

If my final move was a 2-step move, then immediately before that move I must have been at: 

n - 2

Then I take the final two steps: 

n - 2  →  n
         +2

How many ways are there to get to n - 2? 

ways(n - 2)

Therefore, there are exactly ways(n - 2) complete paths to n whose final move is 2 steps.

6. Now Address the Main Doubt

This is where many people initially get confused.

You might think:

"Okay, ways(n - 1) counts the ways to reach n - 1. But then I still have to take the final 1 step. Shouldn't I somehow count that separately?"

The answer is:

No additional multiplication or counting is necessary because there is exactly one possible final move from n - 1 to n.

Look at it this way.

Suppose there are 3 ways to reach step n - 1: 

Path A → n - 1
Path B → n - 1
Path C → n - 1

From each one, there is exactly one final 1-step move: 

Path A → n - 1 → n
Path B → n - 1 → n
Path C → n - 1 → n

So we still have exactly 3 ways. 

3 × 1 = 3

That is why the contribution is simply: 

ways(n - 1)

The same reasoning applies to the final 2-step move.

If there are 2 ways to reach n - 2: 

Path A → n - 2
Path B → n - 2

each has exactly one possible final 2-step move: 

Path A → n - 2 → n
Path B → n - 2 → n

So: 

2 × 1 = 2

giving: 

ways(n - 2)
The final 1-step or 2-step move is already accounted for by the fact that every path reaching n - 1 or n - 2 can be extended by exactly one corresponding final move.

7. Let's See It With n = 4

This is probably the clearest way to make the recurrence feel natural.

All ways to reach step 4 are: 

1 + 1 + 1 + 1
1 + 1 + 2
1 + 2 + 1
2 + 1 + 1
2 + 2

There are 5 ways. 

ways(4) = 5

Now don't look at the entire sequences. Look only at their last move.

Ways ending in 1

1 + 1 + 1 + 1
1 + 2 + 1
2 + 1 + 1

Remove the final 1 from each: 

1 + 1 + 1
1 + 2
2 + 1

These are exactly the 3 ways to reach step 3. 

ways(3) = 3

Then we append the final 1 step to each of those 3 paths. 

ways(3) → +1 → step 4

Therefore: 

3 ways ending in 1

Ways ending in 2

1 + 1 + 2
2 + 2

Remove the final 2: 

1 + 1
2

These are exactly the 2 ways to reach step 2. 

ways(2) = 2

Then we append the final 2 step to each: 

ways(2) → +2 → step 4

Therefore: 

2 ways ending in 2

Combine both groups:

ways(4) = ways(3) + ways(2) = 3 + 2 = 5

8. Why Are We Allowed to Add Them?

Another important question is whether we might accidentally count some path twice.

We don't.

Every path to step n must have exactly one final move.

That final move must be either: 

+1

or:

+2

A path cannot have both as its final move.

Therefore, the two groups are completely separate: 

Paths ending with +1
        +
Paths ending with +2
        =
All paths to n

There is no overlap and nothing is missing.

This is the real reason behind the recurrence: we divide all possible solutions into two mutually exclusive groups based on their final move.

9. The Recurrence Emerges Naturally

Now everything falls into place.

All ways to reach n can be divided into:

  1. Ways whose last move is 1 step.
  2. Ways whose last move is 2 steps.

The first group has ways(n - 1) possibilities.

The second group has ways(n - 2) possibilities.

Therefore:

ways(n) = ways(n - 1) + ways(n - 2)

Notice that we didn't memorize this formula. We derived it from the structure of the problem.

10. Base Cases

To use the recurrence, we need to know where it starts.

One step

For one step, there is only one way: 

1

So: 

ways(1) = 1

Two steps

There are two possibilities: 

1 + 1
2

Therefore: 

ways(2) = 2

From here: 

ways(3) = ways(2) + ways(1)
         = 2 + 1
         = 3

ways(4) = ways(3) + ways(2)
         = 3 + 2
         = 5

ways(5) = ways(4) + ways(3)
         = 5 + 3
         = 8

11. Why This Looks Like Fibonacci

The Fibonacci sequence is: 

1, 1, 2, 3, 5, 8, 13, ...

where each number is the sum of the previous two.

Climbing Stairs produces: 

1, 2, 3, 5, 8, 13, ...

The recurrence is identical: 

ways(n) = ways(n - 1) + ways(n - 2)

The difference is simply where we choose to start the sequence.

The important lesson is not "Climbing Stairs is Fibonacci."

The more useful lesson is:

Many DP problems have a recurrence that looks familiar because the underlying structure is similar. The skill is learning how to derive that recurrence from the problem.

12. The DP Perspective

Now we can define our DP state very simply: 

dp[n] = number of ways to reach step n

To calculate dp[n], we need: 

dp[n - 1]
dp[n - 2]

Therefore: 

dp[n] = dp[n - 1] + dp[n - 2]

This is Dynamic Programming because we are solving smaller subproblems and reusing their answers.

13. Top-Down vs Bottom-Up

Top-Down: Recursion + Memoization

We can start from n and recursively ask for smaller answers. Whenever we calculate a value, we store it so we don't calculate it again.

Conceptually: 

ways(n)
    ↓
ways(n - 1) + ways(n - 2)
    ↓
reuse previously calculated answers

Bottom-Up: Iterative DP

Alternatively, we can start with the smallest known values and build upward: 

ways(1)
ways(2)
ways(3)
ways(4)
...
ways(n)

For this problem, bottom-up is especially simple because we only need the previous two values.

14. Space Optimization

A straightforward DP implementation might store: 

dp[1], dp[2], dp[3], ..., dp[n]

But do we actually need all of them?

To calculate dp[n], we only need: 

dp[n - 1]
dp[n - 2]

After calculating the next value, the older values are no longer needed.

So we can keep only two variables.

If a DP recurrence depends only on the previous few states, you can often reduce the space required by storing only those states.

15. Complexity

With the optimized iterative solution:

Time: O(n)
Space: O(1)

Why is the time O(n)?

We calculate each state from 1 through n exactly once.

Why is the space O(1)?

We only keep the previous two values rather than an entire DP array.

16. The General Pattern to Remember

The most valuable thing to take away from this problem is not the formula itself.

Remember this question:

"What are the possible choices for the final move?"

If the final move can come from only a small number of previous states, the recurrence may be built by combining those states.

For Climbing Stairs: 

Final move = +1
    → came from n - 1

Final move = +2
    → came from n - 2

Therefore: 

ways(n) = ways(n - 1) + ways(n - 2)

17. A Very Important DP Recognition Trick

When you encounter a new problem, don't immediately ask:

"What is the DP formula?"

Instead ask:

  1. What does my state represent?
  2. What is the last decision or move?
  3. Where could I have come from immediately before that?
  4. Can I divide all possible solutions into distinct cases?
  5. Can each case be expressed using a smaller problem?

For Climbing Stairs: 

State:
    ways(n) = number of ways to reach n

Last move:
    +1 or +2

Previous state:
    n - 1 or n - 2

Therefore:
    ways(n) = ways(n - 1) + ways(n - 2)

18. The Core Doubt, Answered in One Sentence

Your concern was:

"Don't we also need to count the final 1 or 2 steps?"

Yes—but there is exactly one way to make that final move from each preceding state, so the number of complete paths ending in +1 is exactly ways(n - 1), and the number ending in +2 is exactly ways(n - 2).

In other words: 

ways(n - 1)
    × one possible final +1 move
    = ways(n - 1)

ways(n - 2)
    × one possible final +2 move
    = ways(n - 2)

And because every path to n must end in exactly one of those two ways:

ways(n) = ways(n - 1) + ways(n - 2)
The recurrence is not saying "ignore the last step." It is saying "classify every complete path according to its last step."

19. Clean Python Implementation

Once the reasoning is clear, the code is almost mechanical: 

def climbStairs(n):
    if n <= 2:
        return n

    prev2 = 1
    prev1 = 2

    for step in range(3, n + 1):
        current = prev1 + prev2
        prev2 = prev1
        prev1 = current

    return prev1

The important thing is that you should now be able to explain the code without memorizing it: 

prev2 = ways(n - 2)
prev1 = ways(n - 1)

current = prev1 + prev2

Each new answer is simply the number of ways to arrive from the previous step plus the number of ways to arrive from two steps before.

Final Mental Model

Imagine yourself standing at step n.

Look backward.

You must have arrived there either: 

from n - 1 by taking 1 step

or:

from n - 2 by taking 2 steps

There is no other possibility.

And all the different ways of getting to those earlier positions have already been counted by ways(n - 1) and ways(n - 2).

So the formula is not a trick to memorize. It is simply a compact way of saying:

"Every way to reach the final step must have come from one of the two possible previous positions."
