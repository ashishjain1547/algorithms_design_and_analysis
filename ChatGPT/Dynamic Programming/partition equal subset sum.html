Partition Equal Subset Sum

1. Restating the Problem

We are given an array of positive integers. Our goal is to determine whether we can divide all the elements into two groups such that the sum of the elements in both groups is exactly the same.

For example:

nums = [1, 5, 11, 5]

We can divide it as: 

[1, 5, 5]  → 11
[11]        → 11

Both subsets have a sum of 11, so the answer is True.

Another example: 

nums = [1, 2, 3, 5]

The total is 11. Since 11 is odd, it is impossible to divide it into two equal integer sums. Therefore the answer is False.

Important: The question is not asking us to actually construct the two subsets. We only need to determine whether such a partition is possible.

2. What Category of Problem Is This?

This is primarily a Dynamic Programming (DP) problem. More specifically, it is a variation of the:

  • 0/1 Knapsack problem
  • Subset Sum problem

The core question eventually becomes:

Can we select some elements whose sum is exactly half of the total sum?

Core DSA concepts being tested

  • Dynamic Programming
  • Subset Sum
  • 0/1 Knapsack thinking
  • Boolean DP
  • Space optimization from a 2D DP table to a 1D array

3. The Mathematical Observation

Let the total sum of all elements be S.

If we want two subsets with equal sums, each subset must have: 

S / 2

Therefore, the first thing we should check is whether the total sum is even.

Total Sum Possible? Reason
Odd No Cannot divide an odd integer into two equal integer sums
Even Maybe We need to determine whether a subset with sum S / 2 exists

So the original problem: 

Can the array be divided into two equal-sum subsets?

becomes:

Does there exist a subset whose sum is total_sum / 2?
This transformation is the key insight. Once you recognize it, the problem becomes a standard Subset Sum problem.

4. What Would the Naive Solution Look Like?

Imagine that for every element we have two choices:

  1. Put it into subset A.
  2. Put it into subset B.

For n elements, this creates approximately: 

2 × 2 × 2 × ... × 2 = 2ⁿ

possible assignments.

We could theoretically try every possibility and check whether the two resulting sums are equal.

The problem is that 2ⁿ grows extremely quickly.

For example: 

n = 10   →       1,024 possibilities
n = 20   →   1,048,576 possibilities
n = 30   →   about 1 billion possibilities

Therefore, brute force is generally not practical for sufficiently large n.

5. The Optimization Insight

Instead of explicitly trying every possible subset, we can keep track of which sums are possible so far.

Suppose our target is: 

target = total_sum / 2

We maintain information such as: 

Can we make sum 0?
Can we make sum 1?
Can we make sum 2?
Can we make sum 3?
...
Can we make sum target?

This is exactly what the Subset Sum DP does.

6. The Key Trick — In Layman Terms

Think of the DP array as a list of achievable scores.

Initially, we know that we can make a sum of zero: 

dp[0] = True

because choosing nothing gives us a sum of zero.

Now suppose the next number is 5.

If we could previously make sum 3, then by taking this 5, we can now make: 

3 + 5 = 8

So whenever a sum s was already possible, adding the current number num makes: 

s + num

possible as well.

In simple terms: We are gradually building a list of all sums that can be created using the numbers seen so far.

The crucial 0/1 Knapsack detail

There is one subtle but extremely important detail.

Each array element can be used only once.

Therefore, when updating the DP array, we process sums from right to left. 

target → ... → num → 0

Why?

Suppose the current number is 3. If we process from left to right, we might create dp[3] and then immediately use that newly-created state to create dp[6].

That would effectively use the same 3 twice.

Going backwards prevents this from happening.

Pattern to remember:
For 0/1 Knapsack or Subset Sum where every item can be used only once, a 1D DP array is usually updated from right to left.

7. Walking Through an Example

Consider:

nums = [1, 5, 11, 5]

The total is:

1 + 5 + 11 + 5 = 22

Therefore:

target = 22 / 2 = 11

We now only need to answer: 

Can we create a subset whose sum is 11?

Start with: 

dp[0] = True

After considering 1, we can make: 

0, 1

After considering 5, we can make: 

0, 1, 5, 6

After considering 11, we can make 11 directly.

Therefore: 

dp[11] = True

We have found a subset whose sum is half of the total.

Consequently, the remaining elements automatically have the other half of the total.

8. Why Does Finding One Half Guarantee the Other Half?

This is another useful observation.

Suppose: 

Total = 22
Subset A = 11

Everything that isn't in subset A must add up to: 

22 - 11 = 11

So we don't need to separately search for the second subset.

Find one subset with sum = total / 2, and the remaining elements automatically form the other subset.

9. Complexity

Let:

  • n = number of elements
  • S = total sum of all elements

The target is S / 2, and for every element we potentially examine every sum up to that target.

Time: O(n × S)
Space: O(S)

More precisely, because the DP only needs to go up to S / 2, the space requirement can be described as O(S / 2), which is simply O(S) in Big-O notation.

10. Why This Satisfies the Constraints

The important point is that we have replaced the exponential O(2ⁿ) brute-force search with a pseudo-polynomial DP approach.

Approach Time Space
Brute Force O(2ⁿ) O(n) recursion stack
2D Subset Sum DP O(n × S) O(n × S)
1D Optimized DP O(n × S) O(S)

The 1D DP is therefore usually the preferred implementation when the constraints make the total sum manageable.

11. Multiple Valid Approaches

Approach 1 — Brute Force / Backtracking

Try every possible assignment of elements to the two subsets.

Advantage: Very intuitive and easy to derive.

Disadvantage: Exponential time, approximately O(2ⁿ).

Useful mainly for understanding the problem or when constraints are tiny.

Approach 2 — 2D Dynamic Programming

Define something conceptually like: 

dp[i][s]

meaning: 

Can we make sum s using the first i elements?

This is straightforward and closely mirrors the classic Subset Sum formulation.

Its time complexity is O(n × S) and space complexity is O(n × S).

Approach 3 — 1D Dynamic Programming

We realize that to process the next element, we don't need the entire history of previous rows. A single array of achievable sums is enough.

This reduces space from: 

O(n × S)

to:

O(S)

This is the preferred approach for the standard problem.

12. The Pattern to Remember for Future Problems

When you see a problem asking whether an array can be divided into groups with equal sums, immediately think: 

Equal partition
      ↓
Calculate total
      ↓
Total must be even
      ↓
Target = total / 2
      ↓
Can I make this target using some elements?
      ↓
Subset Sum / 0-1 Knapsack
      ↓
1D Boolean DP
      ↓
Iterate sums backwards
General DP recognition rule:
If a problem asks whether you can choose some elements to reach an exact target, especially when each element can be used only once, think Subset Sum / 0-1 Knapsack.

13. Clean Python Implementation

Now that the underlying idea is clear, the implementation becomes quite short: 

def canPartition(nums):
    total = sum(nums)

    # The total must be even.
    if total % 2 != 0:
        return False

    target = total // 2

    # dp[s] tells us whether sum s is achievable.
    dp = [False] * (target + 1)
    dp[0] = True

    for num in nums:
        # Go backwards so each number is used only once.
        for s in range(target, num - 1, -1):
            dp[s] = dp[s] or dp[s - num]

    return dp[target]

One-line mental model

Don't try to build two subsets. Just try to build one subset whose sum is half of the total.

That single transformation is the heart of the entire problem.
