Clock Hands Overlap — DSA Explanation

We are given a time such as 01:05, 03:16, or 08:36. Starting from 12:00 midnight, we need to find how many times the hour hand and minute hand overlap, including an overlap that happens exactly at the starting time or exactly at the given ending time.

Important: The examples make the intended interpretation clear: the count starts at 12:00 and ends at the supplied time, and both endpoints are included.

1. Restating the Problem

Imagine a normal analog clock. At exactly 12:00, the hour hand and minute hand are on top of each other.

As time moves forward, the minute hand moves faster than the hour hand. Because of this, the minute hand repeatedly catches up with the hour hand. Every time it catches up, the two hands overlap.

If the input is 01:05, we are asking:

  • Start at 12:00.
  • Move the clock forward until 01:05.
  • Count every instant at which the two hands are exactly on top of each other.
  • Include both 12:00 and 01:05 if an overlap occurs at either endpoint.

For 01:05, there is only one overlap in the interval: the initial overlap at 12:00. The next overlap occurs at approximately 01:05:27, which is slightly after the endpoint 01:05, so it is not counted.

2. What Type of DSA Problem Is This?

This is primarily a mathematical / simulation-avoidance problem. It can be solved with a direct mathematical formula rather than simulating every minute or every second.

The main concepts are:

  • Relative speed
  • Clock-angle mathematics
  • Integer division / floor
  • Careful handling of inclusive boundaries

This is a useful pattern in DSA: sometimes a problem looks like simulation, but the constraints and the underlying mathematics allow us to jump directly to the answer.

3. First Think About the Brute-Force Approach

A straightforward idea would be to examine the clock continuously and somehow check whether the two hands overlap.

But there is a problem: clock hands move continuously. Checking only once per minute is not enough because an overlap can happen between two whole minutes.

For example, after 12:00, the first new overlap does not happen at exactly 01:00. It happens much earlier, after the minute hand has gained enough angular distance to catch the hour hand.

So we could simulate second by second, but even that is conceptually clumsy: we would need to deal with fractional positions, and we are still doing work that mathematics can eliminate completely.

Optimization insight: Instead of asking “Where are the hands right now?”, ask “How frequently do the hands overlap?”

4. The Key Idea: Think in Terms of Relative Speed

This is the most important part of the problem.

The minute hand makes one complete revolution every 60 minutes. Therefore its speed is:

Minute hand = 360° / 60 = 6° per minute

The hour hand makes one complete revolution every 12 hours, which is 720 minutes. Therefore its speed is:

Hour hand = 360° / 720 = 0.5° per minute

The minute hand is therefore gaining on the hour hand at:

6 - 0.5 = 5.5° per minute

So the important number is not the speed of either hand individually. It is the relative speed between them.

5. How Long Between Two Overlaps?

Immediately after 12:00, the hands are together.

To meet again, the minute hand must gain a complete 360° on the hour hand. At a relative speed of 5.5° per minute, the required time is:

360 / 5.5 = 720 / 11 ≈ 65.4545 minutes

So the hands overlap approximately every 65.45 minutes.

That means the overlap times are roughly:

  • 12:00
  • 01:05:27
  • 02:10:54
  • 03:16:21
  • 04:21:49
  • 05:27:16
  • 06:32:43
  • 07:38:10
  • 08:43:38

Notice something very useful: 03:16 is before the overlap at approximately 03:16:21, so only the first three overlaps are included: 12:00, about 01:05:27, and about 02:10:54.

Therefore the answer for 03:16 is 3.

6. Turning This Into a Formula

Suppose the input time is H:MM. We first convert it into the total number of minutes after midnight.

t = H × 60 + MM

For example:

  • 01:05 → 1 × 60 + 5 = 65 minutes
  • 03:16 → 3 × 60 + 16 = 196 minutes
  • 08:36 → 8 × 60 + 36 = 516 minutes

Each new overlap after 12:00 takes exactly:

720 / 11 minutes

Therefore, the number of new overlaps after 12:00 that have already happened by time t is:

floor(t / (720 / 11))

We can rewrite this as:

floor(11 × t / 720)

But remember: 12:00 itself is already an overlap. So we add 1.

answer = floor(11 × t / 720) + 1

7. Let's Verify the Samples

Sample 1: 01:05

Convert the time:

t = 1 × 60 + 5 = 65

Now:

floor(11 × 65 / 720) + 1 = floor(715 / 720) + 1 = 0 + 1 = 1

Correct.

Sample 2: 08:36

t = 8 × 60 + 36 = 516
floor(11 × 516 / 720) + 1 = floor(5676 / 720) + 1 = 7 + 1 = 8

Correct.

Sample 3: 03:16

t = 3 × 60 + 16 = 196
floor(11 × 196 / 720) + 1 = floor(2156 / 720) + 1 = 2 + 1 = 3

Correct.

8. Why the Formula Handles the Boundary Correctly

The phrase “including” in the problem is important.

Suppose the input time were exactly an overlap time. We should count that overlap too.

Using integer division naturally handles this because if:

11 × t = 720 × k

then:

(11 × t) // 720 = k

So the overlap exactly at the endpoint is included.

This is one reason integer arithmetic is preferable here. We do not need floating-point calculations or comparisons involving decimal values.

9. A Very Important DSA Pattern

There is a broader lesson here that is more important than this particular clock problem.

When you see a problem involving something moving, repeating, catching up, or meeting, ask:

  1. What is the speed of each object?
  2. What is their relative speed?
  3. How much distance must one gain to meet the other?
  4. How frequently does the event repeat?
  5. Can I count the number of events directly instead of simulating them?

This is a very common mathematical optimization pattern.

Remember: When two moving things repeatedly meet, often the simplest way to count the meetings is to look at their relative speed rather than simulate their individual positions.

10. Could We Solve It by Simulation?

Yes, but it would be unnecessarily complicated.

We could simulate time in small units, calculate the angle of both hands, and check whether they coincide. However, because the hands move continuously, choosing the simulation step becomes important. A one-minute step can miss an overlap entirely.

We could instead work with exact rational times, but then we would essentially be rediscovering the mathematical formula.

So for this problem, the mathematical approach is clearly preferable.

Approach Idea Time Space
Minute/second simulation Move the clock forward and check hand positions More work, precision issues O(1)
Relative-speed formula Calculate how many 720/11-minute cycles fit in the interval O(1) O(1)

11. Complexity

The optimal solution performs only a fixed number of arithmetic operations. It does not matter whether the input is close to 1 minute, 8 hours, or the maximum possible time.

Time Complexity: O(1)

Space Complexity: O(1)

This is as efficient as we can reasonably get: constant time and constant extra space.

12. Python Solution for HackerEarth

The implementation is intentionally simple. We read the time as a string, split the hour and minute, convert everything to minutes, and apply the formula. 

time = input().strip()

hour, minute = map(int, time.split(':'))

total_minutes = hour * 60 + minute

answer = (11 * total_minutes) // 720 + 1

print(answer)

13. Walking Through the Code

First: 

time = input().strip()

This reads something such as 03:16.

Then: 

hour, minute = map(int, time.split(':'))

The string "03:16" is split into "03" and "16", which are converted into integers 3 and 16.

Next: 

total_minutes = hour * 60 + minute

This converts the entire time into minutes after midnight. For 03:16, that is:

3 × 60 + 16 = 196

Finally: 

answer = (11 * total_minutes) // 720 + 1

The // operator performs integer division, which gives us the number of complete overlap intervals that have occurred. The + 1 accounts for the overlap already present at 12:00.

Final mental model:

The hands start together at 12:00.
The minute hand gains on the hour hand at 5.5° per minute.
It needs to gain 360° to meet it again.
Therefore, two consecutive overlaps are 720/11 minutes apart.
Convert the target time to minutes, count how many such intervals fit, and add 1 for the starting overlap at 12:00.
